# Story 5.1: Define E-commerce and Subscription Schemas

## Status
Done

## Story
**As a** Backend Developer,
**I want** to create the database schemas and JPA entities for Events, Tours, and Subscriptions,
**so that** I can store product offerings and user entitlement data securely.

## Acceptance Criteria
1. A Flyway migration creates an `events` table (id, title, description, cover_photo_url, start_date, end_date, created_at, updated_at).
2. A Flyway migration creates a `tours` table (id, event_id, price, capacity, name, description, thumbnail_url, duration_hours, created_at, updated_at).
3. A Flyway migration creates a `subscriptions` table (id, name, description, price, duration_days, product_id, created_at).
4. JPA entities (`Event`, `Tour`, `Subscription`) are created and correctly mapped to these tables.
5. The `User` entity is verified to correctly map to the existing `subscription_id` and `subscription_expires_at` columns (established in V1/V2 migrations).
6. Relationships are established: `Tour` belongs to an `Event`, and `User` has a `Subscription`.

## Dev Notes
- **Refactoring Boundary Context**: Because the `subscriptions` table was minimally defined inside `V1__init_users.sql` previously to satisfy immediate foreign key constraints, `V5` utilizes an `ALTER TABLE` execution safely wrapping existing architecture bindings with the newer `created_at` parameters smoothly before executing raw `CREATE TABLE` routines on the downstream dependent tables.
- **Monetary Storage Constraints**: `NUMERIC(10, 2)` constraints safely bound into Postgres structures mapping perfectly to `java.math.BigDecimal` models internally negating floating-point drift calculations entirely.

### Testing
- `HotspotIntegrationTest` required moderate refactoring to seed database dependencies correctly due to the newly attached `User` -> `Subscription` Object relationship bindings, preventing raw UUID manipulations natively.
