# Story 6.1: Define Notification Schema and Entity

## Status
Done

## Story
**As a** Backend Developer,
**I want** to create the database schema and JPA entity for storing user notifications,
**so that** I can persist account activity and social interactions for users to view later.

## Acceptance Criteria
1. A Flyway migration creates a `user_notifications` table (id, user_id, message, type, is_read, created_at).
2. The `user_id` column is a foreign key to the `users` table.
3. An index is created on `(user_id, is_read)` to optimize the retrieval of unread notifications for a specific user.
4. A JPA entity `UserNotification` is created and correctly mapped in `com.example.birdlensapi.domain.notification`.
5. A `NotificationType` enum is defined (e.g., `POST_LIKED`, `NEW_COMMENT`, `SUBSCRIPTION_ACTIVATED`).
6. A `NotificationRepository` is created to handle persistence.
7. A test verifies that the JPA entity can be saved and retrieved correctly.
