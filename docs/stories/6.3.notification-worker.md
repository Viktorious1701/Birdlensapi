# Story 6.3: Asynchronous Notification Worker

## Status
Done

## Story
**As the** System,
**I want** a dedicated Notification Worker to consume domain events and generate user notifications,
**so that** users are notified of social interactions and account updates in the background.

## Acceptance Criteria
1. A `@RabbitListener` is implemented to consume messages from the `notifications-queue`.
2. The consumer is only active when the Spring profile `worker` is enabled.
3. The listener correctly handles and distinguishes between:
    - `PostLikedEvent`: Generates a notification for the post owner ("{username} liked your post").
    - `NewCommentEvent`: Generates a notification for the post owner ("{username} commented on your post: {snippet}").
    - `SubscriptionActivatedEvent`: Generates a notification for the subscriber ("Welcome to ExBird! Your premium subscription is now active").
4. The worker retrieves necessary user information (like the actor's username) from the database to construct the human-readable message.
5. The worker persists a new `UserNotification` record for each event.
6. Processing failures are retried 3 times with backoff before being moved to the Dead-Letter Queue (DLQ).
7. An integration test verifies that publishing an event results in a `UserNotification` record appearing in the database.

## Dev Notes
- **Event Dispatching Paradigm**: Employed `@RabbitListener` at the class-level combined with `@RabbitHandler` over distinct method signatures. Because we use `Jackson2JsonMessageConverter`, RabbitMQ injects `__TypeId__` into the headers, allowing Spring to dynamically execute the correct polymorphic function automatically based on the payload type without messy `switch` statements.
- **Fail-Safe Processing**: Allowed Service Exceptions (like `ResourceNotFoundException`) to bubble up naturally into the Rabbit consumer. Throwing it triggers Spring AMQP to utilize its configured retry intervals before dropping corrupted IDs to the DLX.

### Testing
- Activated `@ActiveProfiles({"test", "worker"})` assuring the consumer thread boots in testing environments. Used `Awaitility` simulating true multi-threaded asynchronous consumption, successfully persisting messages natively into PostgreSQL.
