# Story 5.2: Browse Tours and Events API

## Status
Done

## Story
**As a** Mobile Client,
**I want** to browse paginated lists of available Tours and Events,
**so that** I can discover bird-watching opportunities.

## Acceptance Criteria
1. A `GET /api/v1/events` endpoint is created that returns a paginated list of all upcoming events.
2. A `GET /api/v1/tours` endpoint is created that returns a paginated list of all available tours.
3. The responses are read-only and support standard pagination parameters (`page`, `size`, `sort`).
4. Event responses include: `id`, `title`, `description`, `coverPhotoUrl`, `startDate`, `endDate`.
5. Tour responses include: `id`, `name`, `description`, `price`, `capacity`, `thumbnailUrl`, `durationHours`, and the parent `eventId`.
6. Both endpoints are secured with JWT authentication.
7. An integration test verifies that results are returned in the correct paginated format.

## Dev Notes
- **Pagination Contracts**: Deployed strictly typed `EventPageResponse` and `TourPageResponse` wrappers. This keeps caching behaviors (if added later) serialization-safe compared to raw `Page<T>` returns.
- **Sorting Mechanisms**: Defined explicit `@PageableDefault` settings mapped at the Controller layer. Events default to `startDate ASC` keeping immediate opportunities visible first.
- **Data Minimization**: Ensured `TourResponse` outputs `eventId` natively without hydra-loading full `Event` entity relationships across JSON tree outputs, saving substantial mobile bandwidth.

### Testing
- Validated multi-page routing successfully by invoking standard offset sizes against Testcontainers databases. Correctly caught bounds and ordering.
